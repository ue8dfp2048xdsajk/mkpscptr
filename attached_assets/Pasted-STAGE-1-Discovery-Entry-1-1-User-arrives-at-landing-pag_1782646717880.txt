STAGE 2 — Free Testing (No Account Required)
2.1 User drags on background images (or loads example project)
• Backgrounds appear in the grid, no watermark
• User can arrange, reorder, adjust col/row count freely
2.2 User drags on design files
• Designs composite onto all backgrounds
• Watermark appears on every window
• A subtle flash/pulse prompt appears in the top bar: "Remove watermarks — upgrade to a paid plan" with a small ✕ to dismiss
• Prompt persists (or re-appears on hover) until dismissed or user upgrades
2.3 User explores the left sidebar — two categories:
Free features (Layers, Appearance, Mockup sections):
• Apply as normal, no restriction
• Watermark stays but effect is visible
PRO features (Warp & Perspective, Clipping, Painting, Create Pattern, Framing, Background Adjustments):
• Each section header and control shows a yellow ⭐ PRO badge
• User can interact freely — effect is applied and visible on canvas
• That window is now marked with a yellow ⭐ badge (corner of canvas wrapper)
2.4 User selects windows and uses Fabric handles (transform, scale, rotate)
• Works normally for all users
• Watermarks stay in place through all transforms

STAGE 3 — Export Gate
3.1 User clicks Export → dropdown appears
• Options: Export Selected / Export All / PNG or JPG / quality slider
• Export output: ZIP file (default) or folder of individual files (user toggles before exporting)
• Filenames derived from the per-window filename-input labels (e.g. shirt1_design.png)
• Progress indicator shown during export (e.g. "Exporting 12 of 20...")
• If export fails mid-way: error toast with "Retry Export" button — no lost state
3.2 System silently saves project state before redirecting:
• Serialises current project to JSON (including per-window ⭐ PRO star flags and all layer/adjustment state)
• Rate limited: 1 anonymous save per IP per 10 minutes, max 15MB per save
• POSTs anonymously to server → assigned a UUID → stored server-side (expires after 48 hours if unclaimed)
• UUID saved to sessionStorage as fallback
• If the same IP saves again before logging in, overwrites the previous UUID rather than creating a new one
3.3 User is redirected to the Plans page
• Banner: "Export your mockups — choose a plan to continue"
• Annual pricing tab selected by default

STAGE 4 — Login / Create Account
4.1 Options presented:
• Continue with Google (one click)
• Continue with email — enter email + password → account created immediately
• Already have an account? Log in
• Forgot password? → enter email → reset link sent → user clicks link → sets new password → redirected back to where they were
No email verification at this step — verification sent at payment (Stage 5). Frictionless account creation is the priority here.
4.2 After auth completes:
• → Welcome email sent (first-time sign-up only): brief intro, link back to app, link to support
• If came from Branch A (Free) → Dashboard
• If came from Branch B (Starter/Pro) → Stripe Checkout with plan pre-selected

STAGE 5 — Checkout (Stripe)
5.1 Stripe checkout (hosted page or embedded Elements):
• Order summary: plan name, billing period, price
• Discount/promo code field
• Credit/debit card entry
• Links to Privacy Policy + Terms of Service visible in checkout footer
• Pay button
5.2 Payment succeeds:
• Stripe webhook fires → handler updates account plan in database
• Webhook is idempotent: processing the same event twice does not double-upgrade the account (checked via Stripe event ID)
• Receipt emailed immediately
• Email verification link sent at this point (tied to payment confirmation)
• → Dashboard with success banner: "You're now on [Starter / Pro]!"
• Anonymous project UUID linked to account and visible in Projects
5.3 Payment fails:
• Stripe handles card error inline
• User retries — no redirect, no lost state

STAGE 6 — Subscription Lifecycle Events
6.1 Upgrade (Starter → Pro):
• User clicks Upgrade in Settings → Plans page shown with current plan highlighted → selects Pro → Stripe prorates immediately
• Webhook fires → account updated to Pro → access granted instantly
• Confirmation email sent
6.2 Downgrade (Pro → Starter):
• User clicks Downgrade in Settings
• Discount prompt shown first: "Stay on Pro — here's 20% off your next month" with Accept / No thanks
• If accepted: discount applied via Stripe coupon, no downgrade
• If declined: downgrade scheduled for end of current billing period
• User retains Pro access until period ends
• ⭐ PRO-starred windows in existing projects remain flagged — Starter user cannot export them without upgrading again
• Downgrade confirmation email sent
6.3 Cancellation:
• User clicks Cancel Plan in Settings
• Discount prompt shown first (same as downgrade flow above)
• If declined: confirm modal — "Your access continues until [date]. After that your account moves to Free."
• Access continues to end of billing period
• At period end: Stripe webhook fires → account downgraded to Free → cancellation confirmation email sent
• Projects retained but subject to Free tier limits (5 projects, 60-day inactivity expiry)
• Projects over the 5-project limit become read-only (not deleted) — user prompted to upgrade to access them again
6.4 Subscription lapse (payment fails on renewal):
• Stripe retries automatically (3 attempts over 7 days — configurable in Stripe dashboard)
• Payment failed email sent on first failure: "We couldn't renew your plan — update your card" with link to billing settings
• Renewal reminder email sent 3 days before annual renewal date
• If all retries exhausted: webhook fires → account downgraded to Free tier gracefully
• User notified by email: "Your [Starter/Pro] plan has lapsed — resubscribe to restore access"
• Webhook handler is idempotent (Stripe event ID checked to prevent duplicate downgrades)
